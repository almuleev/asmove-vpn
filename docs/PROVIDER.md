# VDSina, совместимость и расходы

Дата проверки открытых источников: **24 ноября 2026**. Аккаунт провайдера не
использовался, реальные заказы/удаления и authenticated API не выполнялись.

## Поддерживаемое предложение

Первая версия: только **VDSina.com / USD / фиксированный тариф / day / cost=0.07**.
[Официальная страница Standard](https://www.vdsina.com/pricing/standard) показывает
1 vCPU, 1 ГБ RAM, 10 ГБ диска и 1 ТБ трафика за $0.07/сутки. На странице указана
доплата за превышение трафика $2.25/ТБ, но сверьте применение к своему тарифу.
Цена в кабинете/API, доступность шаблона Ubuntu 24.04, площадки, квота и minimum
balance важнее рекламного названия. Нельзя считать надпись Standard достаточной.

Код `Vdsina.quote` проверяет active/enable, period, has_params=false, страну DC,
поддержку тарифа шаблоном и ssh-key, минимальные ресурсы шаблона, точную цену и
реальный баланс. ID не зафиксированы: они выбираются из каталога владельца.
При отказе проверки до удаления замена останавливается без удаления. После
удаления тариф/баланс могли измениться — возможен длительный простой без нового EU.

Расход за 30 дней = RU + $2.10 EU + хранение backup + превышение трафика + комиссии.
За 31 день EU = $2.17. Стоимость RU и внешнего хранилища выбирает владелец;
фиксированной проверенной цены совместимого RU здесь нет. В калькуляторе хостинга
учтите публичный IPv4, резервные копии и трафик. Домен необязателен, IP-сертификат
Let's Encrypt не требует покупки сертификата. Необязательные Telegram/ntfy могут
иметь собственные условия. Это не обещание полного VPN за $2.10 в месяц.

## Каталог API без изменений услуг

[Официальная страница API .com](https://www.vdsina.com/tech/api) в доступном публичном
представлении не отдала схему. [Официальное руководство .ru](https://vdsina.ru/files/docs/public_api.pdf)
подтверждает общую структуру v1, Authorization token, GET-каталоги, min_money и
операции server. Это дополнительный источник; он не доказывает равенство условий
.com и .ru. Открыть .com OpenAPI через исследовательский инструмент не удалось.
Перед первым live использованием сверьте документацию своего USD-аккаунта.

`deploy/provider-read.py` вызывает только GET:

| Команда | Endpoint | Что выбрать |
| --- | --- | --- |
| groups | /v1/server-group | group_id |
| plans --group ID | /v1/server-plan/ID | plan_id: active, enable, day, cost=0.07, без конструктора |
| datacenters | /v1/datacenter | datacenter_id и страна вне ru |
| templates | /v1/template | template_id чистой Ubuntu 24.04 amd64, совместимой с планом |
| keys | /v1/ssh-key | ssh_key_id ранее добавленного публичного ключа RU |

API исполняющей службы также читает `/v1/server`, `/v1/server/ID` и
`/v1/account.balance`; после подтверждения удаляет конкретный `/v1/server/ID`
и отправляет POST `/v1/server`. Чтение полного server JSON в публичный вывод не
добавлено: там могут быть пароли. Никогда не публикуйте raw ответы API.

## Права и отзыв

Минимально необходимые **операции**: чтение каталога/баланса/собственных серверов,
создание VPS и удаление подтверждённого VPS. SSH key регистрируется вручную;
исполнитель не нуждается в изменении DNS, аккаунта или других услуг.
Публичные источники не подтвердили наличие scoped token на эти операции.
Не обещаем токен с доступом только к одному VPS: обычный пользовательский token
может иметь гораздо больше прав. Используйте выделенный аккаунт без чужих услуг,
если это допускают правила провайдера; настройте ограничения IP/пользователя,
если они действительно доступны в вашем кабинете.

Токен хранится на RU в `/etc/access-site/infrastructure.env`, root 0600. Web его
не читает. В bootstrap также остаётся приватный входной token file: после настройки
удалите лишнюю копию, убедившись, что env создан и токен работает. Не удаляйте
SITE_ACCESS_KEY. При компрометации сначала отзовите/смените токен в панели и
обновите root env. Руководство .ru связывает смену токена со сменой пароля;
уточните механизм отзыва .com в своём кабинете/поддержке.

## Ошибка или неизвестный результат заказа

Не создавайте новую заявку и не повторяйте POST вручную. Журнал намерения хранится
до запроса; текущий job ищет сервер с уникальным именем `nodeguard-JOB_ID`.
Если ответ потерян, состояние uncertain продолжает сверку. Несколько совпадений,
изменённая личность, отсутствие подтверждения удаления или истёкший этап требуют
внимания владельца. Смена job ID ради повтора способна создать лишний VPS.

Автономного цикла с безусловной арендой нет. Нет месячного бюджета и лимита числа
подтверждённых административных замен; точный тариф и сериализация не ограничивают
суммарные расходы владельца. Код не гарантирует, что у провайдера всегда будет
свободный подходящий адрес, тариф или квота.

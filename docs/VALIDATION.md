Сканирование — защита от известных форматов/привязок, не доказательство отсутствия
любого возможного секрета. В тестах есть публичные DNS-адреса как mocked endpoint;
это не адреса размещения. Исходные пользовательские изображения не переносились.
Встроенный SVG и demo-отчёт созданы заново. Идентификатор source revision и хэши
контрольных сумм не являются ключами доступа.

В процессе проверок исправлены отсутствующий файл нового портала, ссылки на raw
шаблон issue в HTML и кириллические якоря документации. Итоговый прогон относится
к самостоятельному каталогу. FastAPI/httpx выдаёт deprecation warning TestClient;
тесты проходят, переход на httpx2 требует отдельной совместимой проверки.

## Что не проверено

- Чистый реальный Ubuntu VPS, systemd/Nginx/ACME installation и продление сертификата.
- Authenticated .com API, действующая квота/наличие exact-тарифа конкретного аккаунта.
- Реальные аренда/удаление/замена VPS, сетевые HTTPS-запросы через этот новый VPN.
- Клиенты Windows/Android/iOS/macOS/Linux и сети пользователей.
- Настоящий age encryption roundtrip локально (модульные проверки пакета/overwrite
  прошли; Linux CI установит age и запустит этот тест).
- Внешний backup restore на двух чистых узлах, уведомления Telegram/ntfy.
- GitHub Actions / публичный GitHub repo / размещение GitHub Pages.

Docker daemon на рабочем компьютере недоступен; контейнерная Linux-проверка не
выдаётся за выполненную. Не проводились интервью/нагрузочные тесты/аудит безопасности.
Preview-статус сохранён. Production не подключался, реальные VPS/API-операции не
выполнялись. Сетевые запросы исследования касались открытых источников и установки
зависимостей, проверки UI — только loopback.

## Перед stable-релизом

Нужны отдельно разрешённая приёмка чистых Ubuntu 24.04 VPS, безопасная сверка .com
API/квоты, реальные XHTTP/TLS-клиенты на устройствах, продление IP-сертификатов,
внешнее backup restore и review прав/токена. Новичок должен пройти INSTALL под
наблюдением; непонятные шаги исправляются до обещания стабильной установки.
Выберите новый GitHub owner/repo, включите private vulnerability reporting,
проверьте публичный diff и затем отдельно публикуйте по PUBLISHING.md.

# Автоматическая замена VPN-сервера

ASMove VPN может сам заменить зарубежный VPS через API VDSina. Это **удаление
старого VPS и заказ нового**, а не перезагрузка и не переустановка ОС на том же IP.
В первой версии не переключаемся бесшовно: VPN не работает во время восстановления.

## Включить и настроить

При первом запуске мастер `deploy/setup.py` предлагает включение явным ответом `ДА`.
Или откройте админку → Серверы и замены → Автоматическое восстановление.
Поставьте «Включить автозамену», выберите условия, подтвердите автоматическое
удаление и простой и сохраните. Сохранение требует административного сеанса и CSRF.
Без согласия режим не включается. По умолчанию он выключен.

| Поле | Значение по умолчанию | Что означает |
| --- | --- | --- |
| Отказ | HTTPS через VPN не работает | Ни одна из двух разных HTTPS-целей не отвечает через Xray, обе доступны напрямую с наблюдателя |
| Дополнительный отказ | Не требуется | Можно потребовать одновременно недоступность TCP-порта и VPN |
| Неудачных проверок | 3 | Нижняя граница 3, верхняя 20 |
| Длительность сбоя | 180 секунд | От 120 до 3600; одного короткого сбоя недостаточно |
| Пауза между заменами | 3600 секунд | От 600 до 86400 |
| Автозамен за скользящие 24 часа | 2 | От 1 до 10; считаются автоматические разрешения, включая остановившиеся с ошибкой |

Все условия применяются вместе. Порог наблюдений не является точным временем
восстановления: сам probe и циклы таймеров занимают время. Первичная установка
наблюдает с одного RU. Несколько независимых сетей надо добавить отдельно.

## Защита от ошибочной замены и лишних заказов

Неисправный наблюдатель, неработающий Xray-процесс, недоступная контрольная цель,
устаревшие наблюдения и единичный успешный HTTPS через VPN сбрасывают серию.
Проверяется реальный HTTPS через VPN, не просто открытый TCP-порт. Наблюдения
между перезапусками сохраняются в SQLite. Повтор одной временной метки не
увеличивает счётчик; слишком большой перерыв обнуляет серию.

Root-исполнитель перед разрешением делает свежую проверку, проверяет API и архив.
Перед удалением повторяет условия и убеждается, что политика не поменялась.
Сохраняются проверка точного service ID/IP/площадки/тарифа, свежий проверенный
архив, проверка восстановления и журнал намерения перед DELETE/POST.
Одна незавершённая операция с неопределённым результатом блокирует новые операции.
Потерянный ответ API приводит к сверке той же заявки, а не повторному POST.

Отмена заявки администратором блокирует повторную автоматическую заявку того же
инцидента до восстановления и нового эпизода отказа. При attention исправьте
причину в той же заявке. Нет автоматического обхода отсутствующего тарифа,
недостатка средств, плохого архива или неизвестного результата заказа.
Предел автоматики не является бюджетом провайдера и не учитывает все его расходы.
Ручные административные замены этим пределом не ограничиваются.

## Остановить

Снимите «Включить автозамену» и сохраните. Новые автоматические удаления прекратятся;
ещё не начатое удаление проходит повторный gate и останавливается.
Если старый VPS уже удалён, исполнитель продолжает ту же операцию восстановления:
выключение автоматики не должно бросить систему после удаления.
Для аварийного разбора можно остановить `access-site-delete-first.timer` и service
на своём RU, сохранив журнал. Не запускайте новый job вручную после unknown order.

## Важные ограничения

Автоматика не устанавливает причину отказа и не гарантирует, что новый IP поможет.
Нужны доступный RU, API VDSina, баланс, подходящий тариф и свежий проверенный архив.
При долгой полной недоступности EU архив устареет: безопасная процедура остановится.
Сбой после удаления может продлить простой неопределённо. Сохраняются UUID, сроки,
коды и подписки при неизменных RU-origin и SITE_ACCESS_KEY.

Две цели по умолчанию: gstatic generate_204 и Cloudflare trace. Их можно поменять
в root-owned конфигурации наблюдателя `/var/lib/access-site/data/probes/observer.json`,
поле `check_urls` — два разных HTTPS-host без логина/пароля. Редактор целей в UI
пока не реализован. Старый single-target конфиг продолжает работать для ручного
мониторинга, но автозамену не разрешает. Локальные mock-тесты не заменяют проверку
реального VPS: текущая версия остаётся preview.

При восстановлении RU из внешнего экспорта правила сохранены в automation-policy.json,
но автоматически не включаются. Проверьте новую инфраструктуру и включите режим
заново через админку. История суточных автоматических разрешений не переносится.

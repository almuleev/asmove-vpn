# Подробная ручная установка

Для первого запуска рекомендуем [мастер для новичка](QUICKSTART.md). Ниже — ручной путь без мастера.

Маршрут: вручную арендуете RU, устанавливаете контроллер, вручную создаёте первый
EU в VDSina.com с ключом RU, затем подключаете EU к контроллеру. Bootstrap **не
заказывает VPS**. Позднейшие замены через API выполняются вручную или по явно включённым [правилам автоматики](AUTOMATION.md).
На уже установленном узле используйте обновление, а не bootstrap.

## Подготовка: где выполнять команды

«На компьютере» — PowerShell в Windows 10/11 или Terminal в macOS/Linux.
«На RU» — консоль после `ssh root@...` к российскому серверу.
«В консоли EU провайдера» — web/VNC-консоль VDSina, независимая от SSH.
Команды Bash нельзя вставлять в PowerShell, пока вы не подключились к RU.
`REPLACE_...` замените своими значениями; не копируйте примеры адресов как рабочие.
Секреты не вставляйте в issue, URL репозитория, скриншот или чат.

## 1. Выбрать RU и операционную систему

В кабинете выбранного хостинга нажмите создание VPS, выберите физическую локацию
в России, чистую **Ubuntu 24.04 LTS x86_64/amd64**, отдельный публичный IPv4 и root
SSH. Не выбирайте контейнер, ARM, NAT-only или готовую VPN/web-панель.
Рекомендуемый стартовый запас: 2 vCPU, 2 ГБ RAM, 20 ГБ диска. Цену и лимит трафика
проверьте перед оплатой; конкретный RU-провайдер кодом не управляется.

Ожидается: сервер включён, видны IPv4 и способ входа. Если доступен только образ
26.04 или ARM — выберите совместимый образ/другой VPS; проверки ОС не обходите.
Сохраните доступ к web-консоли для восстановления SSH.

## 2. Подключиться с компьютера

В web-консоли RU выполните:

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256
```

На компьютере замените адрес и подключитесь:

```text
ssh -o HostKeyAlgorithms=ssh-ed25519 root@REPLACE_RU_IPV4
```

Сравните показанный SHA256 с консолью; только при совпадении подтвердите `yes`.
Введите пароль из кабинета, если вход по паролю. Ввод пароля невидим — это нормально.
Для входа по ключу добавьте `-i` и путь к **своему** приватному ключу.
Ожидается приглашение `root@...`. `Permission denied` — проверьте root/пароль/ключ;
`timeout` — состояние VPS, порт 22 и firewall. При изменении host key сначала
выясните причину через консоль; не удаляйте доверенный ключ автоматически.
В Windows без команды ssh включите компонент OpenSSH Client в дополнительных
компонентах Windows. В Linux при отсутствии клиента установите `openssh-client`
менеджером пакетов своей системы. На macOS клиент обычно уже есть.

## 3. Передать проверенный исходный код на RU

До публикации основной путь — архив текущего локального коммита, без .git и секретов.
На компьютере в папке ASMove VPN:

```text
git archive --format=tar --output=asmove-source.tar HEAD
scp asmove-source.tar root@REPLACE_RU_IPV4:/root/asmove-source.tar
```

После публикации можно вместо этого клонировать **свой новый** репозиторий и
выбрать проверенный commit/tag. URL GitHub ещё не задан; чужой URL в инструкции
не подставлен. Не используйте PAT в clone URL.

На RU:

```bash
install -d -m 0755 /opt/asmove-src
tar -xf /root/asmove-source.tar -C /opt/asmove-src
cd /opt/asmove-src
bash deploy/bootstrap-host.sh REPLACE_RU_IPV4
```

Все команды установки на RU выполняются от root. Скрипт ставит Nginx, Python,
приложение, Certbot 5.4.0, создаёт пустую базу, уникальные секреты, служебные SSH-ключи
и HTTPS на IP. Внешний firewall RU должен разрешать 22 от администратора, 80 для
ACME и 443 для кабинета. Не открывайте 8016 и локальные туннели.

Ожидается `Controller ready: https://.../admin`. При ошибке ACME проверьте входящий
80, публичный IP, время и лимиты CA. Не отключайте проверку TLS. Если установка
частичная, сохраните файлы/журналы и следуйте [диагностике](DIAGNOSTICS.md); повторный
bootstrap не перезаписывает существующую установку. На этом этапе не создавайте
пользователей с придуманными VPN-ссылками.

## 4. Подготовить VDSina.com

На компьютере откройте [официальный сайт](https://www.vdsina.com/), зарегистрируйте
аккаунт по email и пополните баланс. Нужен USD-аккаунт .com; .ru с рублёвыми ценами
не является заменой. Проверьте возможность заказа Standard за $0.07/сутки в
Нидерландах и наличие **чистой Ubuntu 24.04** на этом тарифе. Не покупайте более
дорогой тариф с расчётом обойти проверку.

В информации пользователя/разделе API кабинета получите постоянный токен.
Названия элементов панели могут меняться; используйте документацию API из кабинета
или уточните у поддержки. Не используйте пароль аккаунта вместо токена.
На RU сохраните токен невидимым вводом, без попадания в историю команд:

```bash
umask 077
read -r -s -p 'VDSina API token: ' provider_token
printf '\n'
printf '%s\n' "$provider_token" > /root/vdsina.token
unset provider_token
chmod 600 /root/vdsina.token
```

Требования к доступу, отзыв и каталог — [PROVIDER.md](PROVIDER.md).
Ошибка 401/403 означает неверный/отозванный токен или политику аккаунта;
повторно не заказывайте сервер ради диагностики.

## 5. Создать первый EU вручную

На RU покажите **публичный** ключ:

```bash
cat /var/lib/access-site/control/id_ed25519.pub
```

В VDSina добавьте его в SSH Keys под своим именем. Нажмите создание сервера:
фиксированный Standard $0.07/день, зарубежный datacenter, чистая Ubuntu 24.04 amd64,
этот SSH key, один публичный IPv4. Не выбирайте предустановленную 3x-ui.
Запишите service ID, IPv4 и datacenter ID, не данные другого аккаунта.
Если тариф недоступен, остановитесь: нет совместимого варианта для этой версии.

В firewall EU разрешите 22 с RU и адреса администратора, 80 для ACME, TCP 443 и
2053 для VPN. Панель 3x-ui останется на loopback, её web-порт не открывайте.
В **web-консоли EU** проверьте:

```bash
uname -m
cat /etc/os-release
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256
```

Ожидается `x86_64`, Ubuntu 24.04 и отпечаток `SHA256:...`.
Если SSH key не был добавлен при заказе, через консоль EU добавьте строку из `.pub`
в `/root/.ssh/authorized_keys` (каталог 0700, файл 0600). Приватный ключ остаётся на RU.

## 6. Найти реальные ID для будущих замен

На RU из `/opt/asmove-src` выполните read-only команды:

```bash
/opt/access-site/current/venv/bin/python deploy/provider-read.py groups --token-file /root/vdsina.token
/opt/access-site/current/venv/bin/python deploy/provider-read.py datacenters --token-file /root/vdsina.token
/opt/access-site/current/venv/bin/python deploy/provider-read.py templates --token-file /root/vdsina.token
/opt/access-site/current/venv/bin/python deploy/provider-read.py keys --token-file /root/vdsina.token
```

Найдите ID группы и подставьте его вместо `REPLACE_GROUP_ID`:

```bash
/opt/access-site/current/venv/bin/python deploy/provider-read.py plans --group REPLACE_GROUP_ID --token-file /root/vdsina.token
```

Ожидаются JSON-списки: тариф активен, `enable=true`, `period=day`, `cost=0.07`,
`has_params=false`; шаблон Ubuntu 24.04 поддерживает тариф и SSH key. Выберите
совместимый datacenter вне RU. `ssh_key_id` — ID ключа **этого RU**.
Не копируйте числовые ID из чужих примеров. Поля каталога описаны в
[PROVIDER.md](PROVIDER.md). Проверка баланса/предложения повторится до удаления
и перед заказом; сам каталог ничего не создаёт.

## 7. Заполнить конфиг и установить EU-компоненты

На RU:

```bash
install -m 0600 deploy/bootstrap.example.json /root/asmove-bootstrap.local.json
nano /root/asmove-bootstrap.local.json
```

Заполните IP/service ID/datacenter первого EU, проверенный `eu_host_fingerprint`,
`country`, `vdsina_token_file: "/root/vdsina.token"` и один объект `candidates`.
Структура объекта есть в `deploy/candidate.example.json`: замените **все** нули
своими ID, `daily_cost` оставьте строкой `"0.07"`. JSON не допускает комментариев
и запятой после последнего поля. Для первой установки `recovery_archive_file=null`.
Telegram/ntfy можно оставить `null`, затем настроить по [OPERATIONS](OPERATIONS.md).

```bash
chmod 600 /root/asmove-bootstrap.local.json
/opt/access-site/current/venv/bin/python deploy/bootstrap-vpn.py /root/asmove-bootstrap.local.json --check
/opt/access-site/current/venv/bin/python deploy/bootstrap-vpn.py /root/asmove-bootstrap.local.json
```

`--check` проверяет только структуру JSON, без SSH/API; он не доказывает правильность
ID, баланса или доступность тарифа. Реальный запуск устанавливает EU, закрепляет
host key, выдаёт новый сертификат IP и проверяет HTTPS через Xray с RU. Ожидается
`ready: true`, `vpn_verified: true`, `replacement_requires_admin: true` для ручного режима.
При несовпадении отпечатка остановитесь и сверьтесь через консоль. При неудаче
VPN-проверки новые ссылки не должны публиковаться; не обходите gate.
Повтор с тем же конфигом продолжает собственную незавершённую установку;
не меняйте IP и не удаляйте приватное состояние ради нового запуска.

Если нужно сначала только проверить VPN без API-управления: токен `null`, кандидаты
`[]` дают режим simulate. Это дополнительный режим, замена реально не выполняется.

## 8. Открыть кабинет и создать пользователя

На компьютере откройте `https://ВАШ_RU_IP/admin` без предупреждения сертификата.
На RU в приватной консоли:

```bash
cat /etc/access-site/initial-admin.txt
```

Сохраните пароль в менеджере паролей. В админке нужен только пароль, без логина.
Создайте тестового пользователя, выберите устройство и срок доступа. Ожидается
шестисимвольный код. Откройте `https://ВАШ_RU_IP/` в другом браузере/приватном окне,
войдите этим кодом. Не отправляйте код публично. Если 502 — проверьте службу
приложения; если создание не удалось — туннель и check-panel, а не повторный заказ EU.

## 9. Подключить устройство

В кабинете нажмите «Копировать ссылку подписки». Установите клиент из официального
источника с поддержкой VLESS XHTTP/TLS: [v2rayN](https://github.com/2dust/v2rayN/releases)
для Windows либо [v2rayNG](https://github.com/2dust/v2rayNG/releases) для Android.
Инструкции для iPhone/V2RC есть в кабинете, но устройства в этой работе не проверены.
Поддержку macOS/Linux и конкретной версии клиента подтвердите отдельным тестом.

Windows: Subscription Group → настройки групп → Add → URL; обновите подписку
через меню Subscription Group, выберите Connection; включите TUN/нужную маршрутизацию.
Android: меню групп подписок → добавить URL → сохранить → обновить подписки →
Connection → запуск; разрешите VPN системным диалогом. Названия меню могут отличаться.

Откройте HTTPS-сайт через включённый VPN. Успех — загрузка содержимого, не ping
порта. При сбое проверьте маршрутизацию, дату/время и TLS. Не включайте allowInsecure.
Отзовите тестового пользователя в админке: доступ должен прекратиться на всех входах.
Восстановите доступ и проверьте снова. Результат RU-наблюдателя и тест телефона
записывайте отдельно.

## 10. Проверить наблюдение и резервную копию

В `/admin/infrastructure` посмотрите свежесть отчётов и проверку готовности архива.
На RU:

```bash
/usr/local/sbin/access-site status
/usr/local/sbin/access-site check-panel
systemctl list-timers 'access-site-*' 'asmove-*'
/usr/local/sbin/access-site backup
```

Ожидается активный мониторинг и свежая копия. Скопируйте зашифрованный экспорт
за пределы RU и проверьте восстановление. Замены не запускайте ради приёмки.
При настоящем сбое используйте выбранный режим: ручное подтверждение IP/простоя
или заранее включённые правила автоматики. Подробный порядок — [OPERATIONS.md](OPERATIONS.md).
Отдельный Pages-кабинет необязателен: [PUBLISHING.md](PUBLISHING.md).
